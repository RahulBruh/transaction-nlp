# Model Card: Transaction Categorizer

## Intended use
Map a raw card-statement descriptor (e.g. `SQ *BLUE BOTTLE COFFEE 4471 SAN FRANCISCO CA`) to a canonical merchant and one of 10 spend categories, as a demo of a merchant-resolution and categorization pipeline. It is a portfolio project, not a production system, and should not drive decisions about real customers.

## Models
| component | model | notes |
|---|---|---|
| Merchant resolver | RapidFuzz `WRatio`, `all-MiniLM-L6-v2` embeddings, or a 50/50 hybrid | Matches against an 80-merchant directory, one entry per alias |
| Baseline classifier | Word (1-2) + char_wb (2-5) TF-IDF + 8 engineered features -> logistic regression (C=10) | Trains in under a second |
| Transformer classifier | `distilbert-base-uncased` fine-tuned 3 epochs, lr 5e-5, batch 32, max length 32 | Trained on CPU |

## Data
- **Fully synthetic.** `txnlp/data.py` generates descriptors from 80 real brand names with seeded noise: processor prefixes (Square, Toast, PayPal), order references, store numbers, city/state suffixes, typos, and 18-25 character truncation like real card networks apply.
- No real cardholder, account or transaction data is used anywhere.
- **Split by merchant:** 2 of the 8 merchants in each category never appear in training. The unseen-merchant test set measures whether a model learned the category or only memorized merchant names.

## Evaluation
See `reports/RESULTS.md` (regenerated by `python scripts/train.py`): resolver top-1 accuracy at two noise levels, classifier accuracy and macro-F1 on seen and unseen merchants, confusion matrices, and accuracy vs. review rate across confidence thresholds.

## Limitations
- Accuracy on seen merchants is close to 100% because test descriptors are new noisy renderings of names the model has already seen. That number says little about real-world performance; the unseen-merchant number is the honest one.
- Synthetic noise is simpler than real statements: no merchant-acquirer codes, foreign-language names, or multi-merchant aggregators.
- One merchant gets one category, but real merchants are ambiguous (Kroger sells fuel, Target sells groceries).
- The category set and the brand list are US-centric.

## Responsible use and escalation
- **Fail toward a human.** If the classifier's top probability is below the review threshold (0.6 by default), the result is returned with `needs_review: true` instead of being silently trusted. `reports/RESULTS.md` shows the trade-off between automation and accuracy at each threshold.
- **Traceability.** Every result reports `source` (`directory` for an exact merchant match, `model` for a prediction), its confidence and the cleaned text it was based on, so a reviewer can see why a decision was made.
- **Reproducibility.** Data generation and training are seeded, and the whole report is rebuilt from one command.
- **Privacy.** Real descriptors can carry location data. A production version should keep them inside the data owner's environment and log only what audit requires.
